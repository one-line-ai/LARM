결론

  • 설정 점검, 기준 상태 비교, 다시 점검해 해결 확인, 상시 감시, 훅 활동 기록, 오프라인 보고서, macOS 앱 화면을 한 번에 제공하는 저장소는 없었습니다. 대부분 한 번 실행하는 CLI이고, 상시 감시는 Snyk 기업용과 tokenwatch뿐이며 둘 다 macOS 네이티브 UI가 없습니다.
  • 가장 큰 비교 대상은 snyk/agent-scan입니다. 지원 도구 폭(14종)과 탐지 항목 수에서 앞서지만 분석 데이터를 클라우드로 보내고, 상시 감시는 기업용에만 있습니다.
  • 설계 철학이 가장 가까운 것은 takahira/agent-trail입니다. 기록만 하고 막지 않으며 파일 내용 대신 요약값만 저장합니다. 다만 프롬프트와 명령 원문은 가린 뒤 저장합니다.

LARM에 없고 다른 도구에 있는 것

SARIF 출력

apisec mcp-audit, MCP-audit이 제공. GitHub 코드 스캐닝 탭에 결과를 올릴 수 있음. LARM 보고서에 findings.json → SARIF 변환을 붙이면 됨.

AI-BOM (CycloneDX 1.6)

apisec mcp-audit이 제공. 사용 중인 MCP 서버·모델·API 목록을 부품 명세서로 내보냄. LARM의 inventory.json과 내용이 거의 같아 변환 비용이 낮음.

도구 오염·프롬프트 주입 탐지

snyk, cisco가 MCP 서버의 도구 설명 텍스트를 분석. LARM은 설정 파일만 보고 서버에 접속하지 않으므로 의도적으로 제외한 영역. 요건정의서에서도 후속 검토로 분류됨.

실행 전 차단

guardrail, agent-guard, permissions-hook이 제공. LARM은 사용자 결정으로 관측 모드만 제공(F42·F43 제외).

토큰 저장 위치 80여 곳

tokenwatch가 AI 도구 외에 SSH·AWS·브라우저까지 자격증명 위치를 목록화. LARM은 Claude·Codex 자격증명 파일 권한만 확인.

지원 도구 폭

snyk agent-scan이 14종. LARM은 3종(Claude Code·Codex·Cursor)이며 요건정의서 후속 A 단계에서 확대 예정.
