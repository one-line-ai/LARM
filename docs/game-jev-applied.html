게임이론·Jev, 제품에 들어간 것

설계 문서(10장, 플레이어 = 사용자·AI 도구)에서 실제로 0.7.0에 구현된 항목만 정리한 문서. 무엇이 어느 화면에서 어떻게 동작하는지, 어떤 값이 저장되는지, 무엇이 아직 아닌지를 구분한다.

한 줄 요약. 위험 판정은 여전히 규칙(R01~R08, RR01~RR02)이 한다. 게임이론은 언제 검사하고, 무엇을 알리고, 무엇을 먼저 볼지만 바꿨다. Jev는 아직 연결되지 않았고, 그 자리에 규칙 기반 추정(rule-1)이 들어가 같은 질문에 답한다.

0. 게임이론이 왜 여기에 쓰이는가

게임이론은 서로 다른 목표를 가진 둘 이상이 상대의 선택을 보고 자기 선택을 정하는 상황을 다루는 도구다. 체스나 도박만이 아니라, "내가 이렇게 하면 상대는 어떻게 할까"가 있는 모든 상황이 게임이다. LARM이 다루는 상황이 정확히 그렇다.

LARM의 상황을 게임으로 보면

플레이어
사용자(일은 끝내되 위험은 줄이고 싶음)와 AI 도구(일을 빨리 끝내고 싶어 넓은 권한과 지름길을 택함). 둘의 목표가 겹치지만 같지는 않다. AI 도구에 악의가 없어도, 주입된 지시에 조종당하면 목표가 바뀐다.
LARM의 자리
플레이어가 아니라 심판. 무엇을 기록하고, 무엇을 보여 주고, 어떤 기본값을 둘지 정해 두 플레이어가 받는 정보와 이득을 바꾼다. 막지 않고도 행동을 바꾸는 이유가 여기 있다.
왜 규칙만으로 부족한가
규칙은 "이 설정은 위험하다"를 판정한다. 그러나 언제 다시 볼지, 무엇을 먼저 알릴지, 얼마나 두고 볼지는 상대의 행동에 달려 있고, 이건 규칙이 아니라 전략의 문제다.

다섯 게임을 한 문장씩

  1. 권한 위임 (주인·대리인 게임): 넓은 허용을 줄이면 안전해지지만 확인 요청이 늘어 귀찮아진다. 어느 규칙은 좁혀도 확인이 거의 안 늘어나는지를 실제 활동 기록으로 계산해 보여 주면, 사용자는 귀찮음이 아니라 숫자로 결정할 수 있다.
  2. 신호 읽기 (신호 게임): 조종당한 AI 도구와 정상인 AI 도구는 겉으로 같아 보이지만 행동(숨긴 명령, 민감 경로 접근)이 다르다. 행동을 기록해 두면 그 차이가 "신호"가 되어 둘을 가를 수 있다. 신호가 강한 세션부터 보여 준다.
  3. 기억 있는 신뢰 (반복 게임): 기억이 없으면 위험한 변경을 한 뒤에도 다음 세션에 같은 신뢰를 준다. 프로젝트별로 이력을 남겨 "지난번에 어겼으면 이번엔 더 살펴본다"가 가능하게 한다(팃포탯).
  4. 검사 (검사 게임): 30분마다 정확히 검사하면 그 사이가 안전한 틈이 된다. 간격을 무작위로 하면 틈이 없어지고, 작업 중에는 더 자주 보아 놓치는 시간도 줄어든다.
  5. 주의 배분 (늑대소년 게임): AI 도구는 사건을 무한히 만들 수 있지만 사용자의 주의는 유한하다. 알림 하나의 가치(조치가 필요할 확률 × 사용자가 볼 확률)가 낮으면 보내지 않아야 알림의 무게가 유지된다. 높은 위험은 예외 없이 보낸다.

Jev의 역할은 이 다섯 게임에 필요한 확률(바뀔 확률, 조치 필요 확률, 볼 확률, 조종당했을 확률)을 대는 것이다. 지금은 규칙 기반 추정이 그 자리를 대신하고 있어 값이 거칠지만, 구조는 같다.

1. 다섯 게임의 적용 현황

게임사용자의 선택AI 도구의 선택제품에서 하는 일화면상태
1. 권한 위임허용 범위를 넓힐지 좁힐지주어진 범위를 끝까지 씀넓은 허용 규칙(R02)마다 최근 30일 활동 기록으로 "좁히면 늘어날 확인 요청"을 세션당 횟수로 계산. 2회 이내면 좁혀도 부담이 작다고 안내발견 사항 상세 "좁히면 어떻게 되나", 사용자와 AI 도구 1번적용됨
2. 신호 읽기계속 맡길지, 살펴볼지행동 자체가 신호세션별 "살펴볼 필요" 점수를 숨김·우회형 명령, 높은 위험 판정, 민감 경로, 범위 밖 접근 수로 계산해 순서를 매김. "살펴봄, 문제 있음/없음"으로 결과 기록AI 도구 활동 상단, 사용자와 AI 도구 2번, 한눈에 보기 타일적용됨
3. 기억 있는 신뢰프로젝트마다 얼마나 믿을지안전한 변경만 할지, 위험한 설정 변경을 할지범위별 최근 30일 새 발견·반복 발견·미조치 높음 건수로 안정/주의/살펴볼 필요 표시. 높은 위험이 없으면 기준 상태 저장을 권장(G3)사용자와 AI 도구 3번적용됨
4. 검사언제 다시 확인할지언제 설정을 바꿀지전체 대조 간격을 변경 확률로 정하고 0.7~1.3 무작위 곱을 섞음. 작업 중 10~15분, 유휴 30~60분(G1)한눈에 보기·개요의 "다음 대조", 사용자와 AI 도구 4번적용됨
5. 주의 배분알림에 반응할지사건을 얼마든지 만듦중간 위험·감시 공백 알림은 조치 필요 확률 × 반응 확률 − 비용이 문턱을 넘을 때만 전송, 아니면 배지(G2). 오늘 확인할 항목을 조치 필요 추정 순으로 정렬하고 "확인하면 알 수 있는 것"을 붙임(G6)알림, 한눈에 보기·개요 "오늘 확인할 항목", 사용자와 AI 도구 5번적용됨
약속 장치예외를 얼마나 둘지훅 등록으로 기록됨을 앎같은 항목에 예외를 2번 이상 두면 "되풀이되는 예외는 허용과 같음" 안내와 7일 권장(G5). 훅 등록은 기존 기능발견 사항 상세 "예외와 검토"일부 기본값 자동 축소는 안 함, 안내만

3. Jev 자리

결정 층은 프로토콜 DecisionLayer로 분리되어 있다. 질문(Q1, Q2, Q4, Q5), 입력(DecisionInput), 답(Estimate: 확률·근거·모델 버전)의 형태가 고정되어 있어, Jev 클라이언트가 이 프로토콜을 구현하면 화면·저장·검증은 그대로 쓰인다.

항목지금Jev 연결 시
구현체HeuristicDecisionLayer (모델 "rule-1")Jev 호출 계층 (모델 "jev-<버전>")
화면 표시"참고 추정(규칙)""참고 확률 · Jev v…"
입력미조치 높음 수, 15분 활동 수, 마지막 변경 경과, 반응률, 조용한 시간같은 입력 + 세션 행동 순서, 프로젝트 이력 (모두 별칭·지문만)
실패 시해당 없음rule-1로 즉시 후퇴, 화면에 "규칙만 사용 중" 표시
미확정Jev 호출 방식(로컬 프로세스인지 API인지), 요청·응답 스키마, 지연 시간, 비용. 이것이 정해져야 연결 작업을 시작할 수 있음

4. 저장되는 것과 저장되지 않는 것

  • 저장됨: 추정 확률과 근거 문장, 대상 식별자(세션 참조, 발견 사항 ID), 알림 전송·반응 시각, 예외 결정 수.
  • 저장 안 됨: 명령 원문, 파일 내용, 실제 경로. 세션 점수는 이미 별칭·표시(flag)만 남은 활동 기록에서 계산.
  • 증빙 보고서: 추정값은 보고서 ZIP에 들어가지 않음. 판정과 근거만 들어감(F25 범위 유지).

5. 관측 모드와의 경계

모든 적용 항목은 순서·타이밍·기본값·안내만 바꾼다. 허용·차단 결정(F42·F43)은 하지 않으며, 규칙을 실제로 좁히거나 예외를 줄이는 것은 사용자가 직접 한다. 자체 시험은 DecisionTests 7건(간격 경계·무작위성, 게이트, 추정 경계, 브라이어, 세션 순서, 위임 계산, 기준 권장)으로 검증했다.
