"적용"은 요건의 동작이 제품에 들어가 자체 시험이나 이 Mac에서의 확인을 거친 상태, "부분"은 동작은 있으나 요건의 시험 일부(실기·독립 검증·장기 시험)가 남은 상태입니다. 자체 통과는 개발자 자동 시험 33개의 결과이며 독립 검증(LG2)이 아닙니다.

범위 결정

  • 조건부 요건 제외. F42(실행 전 확인)·F43(정책 집행)·N15(조건부 통제 무결성)는 요건정의서 11.1에 따라 관측 모드로 제한합니다. Claude Code hook은 허용·차단 결정을 반환하지 않고 기록만 합니다. 시험 T54·T55·T59는 비적용으로 기록했습니다.
  • 서명. ad-hoc 서명으로 배포합니다. Developer ID 서명·공증(N06)은 출시 게이트 LG5 항목으로 유보했습니다.
  • 지원 도구. Claude Code·Codex CLI 설정 점검과 Claude Code hook 활동 기록을 지원합니다. Cursor는 MCP 설정 점검만 지원하며 이 Mac에 설치돼 있지 않아 fixture로만 검증했습니다.
  • 기술 방식. SwiftPM 네이티브 앱(외부 의존성 0). 룰과 안내는 데이터 파일이고 실행 코드가 아닙니다. 모든 기능이 오프라인으로 동작합니다.

기능 요건 F01~F44

F01

설치 후 첫 점검

부분

서명된 macOS 앱에서 계정 가입 없이 점검 범위 확인, 첫 점검, 결과 열기까지 한 흐름으로 제공한다. 처음 실행할 때 읽을 위치와 저장할 정보를 설명한다. 첫 점검 뒤 자동 시작·활동 연동·알림 사용 여부를 확인하고 시험 이벤트로 감시 상태를 확인한다.

수용 기준 새 사용자 계정에서 설치 후 5분 이내 결과 화면에 도달한다. 지원 대상이 없으면 0건 안전 판정 대신 “지원 대상 없음”과 폴더 추가 방법을 표시한다.

제품 적용

설치 스크립트 또는 DMG로 설치한 뒤 계정 가입 없이 첫 점검과 결과 화면까지 한 흐름. 첫 실행 안내에 읽는 위치와 저장 정보를 표시. 지원 대상이 없으면 "점검할 지원 대상이 없습니다"와 프로젝트 추가 안내. 자동 시작·알림·hook 연동은 설정 화면에서 선택.

화면·구성요소: 개요, 증빙과 설정 · 시험 T01

F02

명시적 점검 범위

적용

기본 사용자 설정 위치와 사용자가 선택한 프로젝트만 읽는다. 변경된 설정 루트는 사용자가 등록하고 화면에서 확인한다. 홈 전체·다른 사용자·클라우드 동기화 병합은 자동 탐색하지 않는다.

수용 기준 등록 20개 프로젝트를 재실행 후 복원한다. 범위 밖 심볼릭 링크, 권한 거절, 제외 폴더를 읽지 않으며 각각 점검 제외 사유를 기록한다.

제품 적용

사용자 설정 위치와 사용자가 추가한 프로젝트만 읽음. 홈 전체·다른 사용자·클라우드 병합은 탐색하지 않음. 범위 밖 심볼릭 링크·권한 거절·제외 폴더는 읽지 않고 사유를 남김.

화면·구성요소: 개요 > 점검 범위 · 시험 T02

F03

지원 대상 식별

적용

Claude Code, Codex CLI와 Cursor MCP 설정을 어댑터별로 식별한다. 설치 식별과 구성 존재를 구분한다. 파일·앱 메타데이터를 사용하고 발견한 실행 파일을 실행해 버전을 알아내지 않는다. 정적 점검 지원과 실행 이벤트 연동 지원을 별도 항목으로 표시한다.

수용 기준 가짜 claude 실행 파일을 넣어도 실행되지 않는다. 버전 불명과 미설치·설정 잔존을 구분한다. 지원 버전 미확인은 제한 지원 상태로 표시한다.

제품 적용

Claude Code·Codex·Cursor를 어댑터별로 식별. 실행 파일을 실행하지 않고 심볼릭 링크 대상·Info.plist에서 버전을 읽음. 설치됨·설정 잔존·미설치, 버전 불명을 구분하고 시험 버전 밖은 제한 지원으로 표시.

화면·구성요소: 개요 > 지원 도구 · 시험 T03

F04

설정 출처와 우선순위

적용

JSON/TOML을 안전하게 파싱하고 각 값에 어댑터 버전, 원본 위치, 설정 범위, 해석 근거를 붙인다. 벤더별·버전별 우선순위를 적용한다. 실제 세션의 CLI·환경·관리 정책이 관측되지 않으면 유효 설정 확정을 보류한다.

수용 기준 서로 충돌하는 관리·사용자·프로젝트 설정을 정확히 구분한다. 중복 키, 파싱 실패, 미지원 키는 조용히 무시하지 않는다. 가정한 프로젝트 신뢰 상태를 명시한다.

제품 적용

JSON·TOML 안전 파서(중복 키 거부, 미지원 문법은 미지원으로 보고). 값마다 어댑터 버전·위치·범위·우선순위(managed > local > project > user)를 기록. Codex profile을 읽지 못하면 유효값 보류.

화면·구성요소: 발견 사항 상세 > 출처 · 시험 T04

F05

MCP 구성 목록

적용

지원 설정에 선언된 MCP 서버와 에이전트별 연결을 목록화한다. 이름, 전송 방식, 명령 유형, 인자 개수, URL의 scheme·host·port, env/header 키 이름을 보존한다. 원문 인자와 토큰은 저장하지 않는다.

수용 기준 3개 어댑터·50개 MCP 정의에서 누락 없이 읽거나 누락 사유를 낸다. 동명 서버는 에이전트·scope·설정 위치로 구분한다. tools/list 호출, 서버 실행, URL 접속은 0건이다.

제품 적용

MCP 서버 이름·전송 방식·명령 종류·인자 개수·URL의 scheme/host/port·env/header 키 이름만 보존. 원문 인자·토큰은 저장하지 않고 서버 실행·URL 접속 없음.

화면·구성요소: 그래프, 증빙 inventory.json · 시험 T05

F06

승인 정책 점검

적용

승인 질의 여부와 도구 허용 범위를 별도 속성으로 표시한다. 승인 생략 설정은 사용자가 검토할 위험 신호이며, 샌드박스 해제와 같은 의미로 취급하지 않는다.

수용 기준 Codex approval_policy=never + read-only와 never + danger-full-access를 서로 다른 결과로 표시한다. 관측하지 않은 실행 플래그는 “미관측”으로 남긴다.

제품 적용

승인 정책(approval_policy, defaultMode)과 샌드박스 설정을 별개 속성으로 표시. 관측되지 않은 실행 플래그는 "확인 안 됨".

화면·구성요소: 발견 사항 R01 · 시험 T06

F07

파일·네트워크 경계 점검

적용

읽기·쓰기 범위, 샌드박스 구성, 외부 네트워크 허용 설정을 분리해 표시한다. 명시된 구성과 실행 시 적용 여부를 구분하며 근거가 없는 보안 점수를 생성하지 않는다.

수용 기준 지원 fixture의 제한·확장·알 수 없음 3상태를 구별한다. sandbox 키 하나가 켜져 있다는 이유로 민감 경로·통신이 안전하다고 판정하지 않는다.

제품 적용

읽기·쓰기·샌드박스·네트워크 설정을 분리해 표시하고 제한·확장·미관측 3상태를 구별. 점수화하지 않음.

화면·구성요소: 발견 사항 R01 · 시험 T07

F08

넓은 허용 규칙 식별

적용

문서로 확인된 어댑터 문법의 전체 셸 허용·광범위 쓰기·도구 와일드카드 등을 식별한다. 개별 allow/ask/deny의 범위와 해석 가능 여부를 함께 보여준다.

수용 기준 유효 광범위 허용, deny로 제한된 규칙, 해석 불가 패턴을 별도 표시한다. 단순히 rm·curl 문자열이 들어 있다는 이유로 실행·악성 여부를 단정하지 않는다.

제품 적용

허용 규칙 문법을 해석해 전체 셸·광범위 쓰기·MCP 와일드카드·네트워크 와일드카드를 식별. deny로 막힌 규칙과 해석 불가 규칙을 별도 표시.

화면·구성요소: 발견 사항 R02 · 시험 T08

F09

엔드포인트 검토

적용

명시된 원격 MCP·모델 엔드포인트의 새 등록, 변경 및 비루프백 평문 HTTP를 표시한다. 사용자 검토 목록은 정확한 host·scheme·port·scope 단위로 관리한다.

수용 기준 회사 프록시를 등록하면 “검토 완료”만 표시한다. 토큰·URL userinfo·query·fragment는 저장하지 않는다. 인증 헤더 부재를 무인증 확정으로 해석하지 않는다.

제품 적용

비루프백 평문 HTTP와 미검토 원격 엔드포인트를 host·scheme·port 단위로 표시. "엔드포인트 검토 완료" 기록으로 해당 주소만 검토 처리. userinfo·query·fragment는 저장하지 않음.

화면·구성요소: 발견 사항 R06 · 시험 T09

F10

비밀정보 후보 점검

적용

지원 설정 파일의 env/header·토큰 키와 승인된 비밀정보 파일을 로컬에서 검사한다. 구조·패턴·엔트로피의 근거를 구분하고 유효성 확인을 위한 외부 요청은 하지 않는다.

수용 기준 합성 fixture의 확정 형식 40개를 모두 찾고 음성 100개에서 오탐 5개 이하를 목표로 한다. 실제 키 유효성은 항상 미확인이다. 변수 참조와 평문 값을 구별한다.

제품 적용

알려진 토큰 형식 14종과 고엔트로피·민감 키 이름 근거를 구분. 합성 40종 전부 탐지, 음성 100종 오탐 5 이하를 시험으로 고정. 외부 검증 요청 없음.

화면·구성요소: 발견 사항 R03 · 시험 T10

F11

민감 파일 권한 점검

적용

지원 자격증명 위치 및 비밀정보 후보가 있는 파일의 소유자·POSIX 권한을 확인한다. 읽기 범위가 불명확한 ACL 등은 확인 필요로 남긴다. 시스템 전체 자격증명 저장소는 읽지 않는다.

수용 기준 0600/0644/타 소유자/권한 거절 fixture를 구분한다. 권한이 넓다는 사실과 유출 발생을 구별하며, 읽지 못한 파일을 비밀정보 없음으로 집계하지 않는다.

제품 적용

자격증명 저장 위치와 비밀정보 후보가 있는 파일의 소유자·POSIX 권한 확인. ACL은 확인 필요로 남김. 내용은 읽지 않음.

화면·구성요소: 발견 사항 R04 · 시험 T11

F12

프로젝트 사전 검토

적용

사용자가 고른 프로젝트의 지원 설정, MCP 선언, CLAUDE.md·AGENTS.md 및 등록된 지시·훅·스킬 파일의 존재·변경을 확인한다. 실행 가능한 설정의 존재와 실행 발생을 구분한다.

N11

시각과 기록 의미

적용

UTC ISO 8601과 사용자의 시간대를 함께 기록하고 scan_id·단조 증가 sequence를 둔다. 기간 비교는 관측 시점을 사용한다. 파일 mtime만으로 변경 주체나 실제 실행 시점을 추론하지 않는다. 활동 이벤트에는 원천 생성·수집 시각과 source_event_id를 분리한다. PID 재사용은 시작 시각·세션 식별자로 구별하며 시계 불명 시 전체 지연을 미측정으로 표시한다.

수용 기준 시계 역행·타임존 변경 fixture에서 순서를 복원한다. 서명/외부 타임스탬프 없는 기록을 공증 시점으로 표시하지 않는다. 기록 삭제·내보내기·예외도 로컬 이력에 남는다.

제품 적용

UTC ISO 8601과 시간대 병기, scan_id·단조 sequence. 활동 이벤트는 발생·수신 시각과 source_event_id 분리, PID는 시작 시각과 함께. 삭제·내보내기·예외를 감사 기록.
